## 1. 背景与定位

### 1.1 为什么是 v0.86

v0.85.0 完成 Plugin SDK 100% + Event 统一输入 100% + Runtime event-driven 50%. 6 kernel-deepening 全部落地. 下一阶段突破 12-kernel-mapping §8.2 0-20% 缺失清单的 3 个核心组件 (per handoff doc "v0.86+" 规划):

1. **Goal Ontology** (§2.3) — BloomProfile 只有 6 层, 不是 Goal Ontology. 缺 Capability / Objective / Metric / Evidence 完整表达
2. **Twin Consistency** (§2.1) — 跨 Profile 校验缺失 (K mastery + Bloom L3 + TC 通过 一致性没有保证)
3. **Thompson Sampling** (§1.3) — Policy Engine 只有 LinUCB, Thompson Bayesian Beta Bandit 0%

POMDP Policy 推迟 v0.87+ (单 commit 太重, 跟 Thompson 同 commit 测试量翻倍).

### 1.2 战略选择: 3 主轴 + 1 Integration 同时

3 主轴是独立的设计层 (Goal=对象, Twin=校验, Thompson=策略), Integration 是 glue (把 3 主轴串进 Runtime API). 不分两个版本做的原因:
- Goal Ontology 不接 Runtime 永远只算 schema migration
- Twin Consistency 不在 Runtime.plan 触发等于没做事 (跟 v0.85 Plugin SDK 不到 if __name__ 块同理)
- Thompson 不接 PolicyLearner 永远只算 toy algorithm

### 1.3 4-sub-commit 切分 (Bisen 拍板 2026-08-11)

| Sub | 范围 | 依赖 |
|---|---|---|
| a | Goal Ontology (Capability → Objective → Metric → Evidence) + 关联 BeliefState + 升级 GoalCompletion | 无 |

### 4.2 Thompson Sampling 算法

```python
class ThompsonSampling:
    """贝叶斯 Bandit: 每 arm 维护 (alpha, beta), 采样 Beta(α, β) 选 argmax.

    适用: reward ∈ [0, 1] (符合 Beta 分布假设)
    冷启动: 全部 arm 初始化 (α=1, β=1) uniform prior
    持久化: dump_state (α/β 矩阵) + load_state (跟 LinUCB A/b 矩阵同 storage)
    """
    def __init__(self, n_arms: int):
        self.alpha = np.ones(n_arms)  # success + 1
        self.beta = np.ones(n_arms)   # failure + 1

    def select_arm(self, context: np.ndarray) -> int:
        samples = np.random.beta(self.alpha, self.beta)
        return int(np.argmax(samples))

    def update(self, arm: int, reward: float) -> None:
        self.alpha[arm] += reward
        self.beta[arm] += (1 - reward)
```

### 4.3 关键不变量

- **接口同构**: `select_arm(context) -> int` + `update(arm, reward): None` + `dump_state() -> dict` + `load_state(state)` 跟 LinUCB 100% 同
- **冷启动**: 默认 LinUCB (向後兼容 v0.82.0-d 4-layer 架构), 显式 `policy_type="thompson"` 切换
- **持久化**: states 表 schema 不变 (复用 `dump_state` dict), Thompson (α/β) 透过 `policy_type` 字段在 dump 加 key
- **PRNG seed**: v0.86.0-c 测试用固定 seed, production 走系统 entropy (跟 v0.82 LinUCB 不同, LinUCB 是 deterministic)
- 防御性自检 [8] **仍 hard block** (ThompsonSampling 不 mutate state)
- H3-c4 canary **PASS**

### 4.4 PolicyLearningPolicy 升级

```python
# ecos/lca/l4_optimization/policy_learner.py
class LCAPolicyLearner:
    def __init__(self, ..., policy_type: str = "linucb"):
        self.policy_type = policy_type
        if policy_type == "linucb":
            self._impl = LinUCB(...)
        elif policy_type == "thompson":
            self._impl = ThompsonSampling(...)
        else:
            raise ValueError(f"Unknown policy_type: {policy_type}")

    def select_arm(self, context): return self._impl.select_arm(context)
    def update(self, arm, reward): self._impl.update(arm, reward)
    def dump_state(self) -> dict:
        return {"policy_type": self.policy_type, "params": self._impl.dump_state()}
```

## 6. 5 个设计决策 (Bisen 拍板 2026-08-11)

### 6.1 Goal Ontology 的 Evidence 归属

**决策**: `Goal.evidence_ids` 走现有 Evidence Engine (add_evidence / evidence_for), 不引入新 mutation path.

**为什么不独立 Evidence store**: Evidence Engine v0.83.0-a 已 6 字段 + 6 来源, 复用避免双重 source-of-truth. Goal 关联 Evidence 是 relationship, 不是新 entity.

### 6.2 Twin Consistency 触发时机

**决策**: Runtime.plan 选 intervention 前 (per Bisen 决策 3).

**为什么不在 StateEngine.commit 后**: 异步触发允许 intervention 已发出, 后悔成本高. Runtime.plan 前触发是"前置 defensive", 失败拒答 + 转 fallback.

**为什么不同时 Runtime.evaluate**: 评估时已不可改 (干预已执行), 教学价值低. 触发点放在规划阶段.

### 6.3 Thompson Sampling 冷启动策略

**决策**: 默认 LinUCB (向後兼容 v0.82.0-d 4-layer), 显式 `policy_type="thompson"` 切换.

**为什么不默认 Thompson**: LinUCB 已稳定 50+ 学生跑 (lbc001 + lbc002 + 其他人), Thompson 是新算法, 默认切换风险高. 显式 kwarg 让 Bisen 单独账号跑 Thompson 实验对比.

### 6.4 是否合并 v0.86.0-d 到 0.86.0-c

**决策**: 独立 commit.

**为什么不合并**: c = 纯算法 (Thompson 实现), d = Integration (Runtime API 串 3 主轴). c 失败回滚不影响 d 设计; d 失败回滚保留 c 算法. 风险隔离.

### 6.5 是否推进 POMDP Policy

**决策**: **不推进, 推迟 v0.87+** (per Bisen 决策 2).

**为什么不放 v0.86**: POMDP 需要 observation model + belief MDP 推理, 单 commit 难做扎实. v0.86 优先 Bayesian Bandit (Thompson), POMDP 留 v0.87 单独版本.
