# 会话记录: /api/answer 不持久化 + judge "无 token 消耗" — 幽灵学生 bug 根因

- **日期**: 2026-08-19
- **主题**: v0.96.9 — 学生端答题后轨迹/历史不更新 (系统永远记录 45 次), 状态更新落到 skill_id 命名的幽灵学生
- **参与者**: Bisen (反馈 + 复现), Mavis (排查 + 修复)
- **性质**: 功能 bug 修复, `__version__` 0.96.8 → 0.96.9

## 症状 (Bisen 用 lbc002 反馈)

1. AI 评判能返回正确结果 (实测 judge 确实调用 MiniMax-M3, 4.6s 返回) — "无 token 消耗" 是 MiniMax 控制台延迟/看错, 非代码问题
2. 答题后轨迹快照 + 答题历史没有新数据, 系统仍记录 45 次 (实际答了 46 次)

## 排查过程

1. **实测复现**: POST /api/answer 返回 `persisted=True`, 但 DB `warmup_count` 不变 (45)、theta 永远是 7/28 的旧值; `/api/state` 读的是内存 `_STUDENT_STATES`, 显示轨迹冻结在 7/28
2. **DB 冒烟**: 发现 `students` 表有以 skill_id 命名的幽灵学生 — `python.loops` (测试时创建)、`cross_subject` (用户 11:30 答题时创建), `last_active_at` 与 lbc002 答题时间精确同步
3. **隔离复现**: 独立进程 + 真实代码路径稳定复现; 直接调 `engine.update` 正常 (warmup 45→46), 走 Plugin bus 路径不更新 → 定位到 subscriber

## 根因

```
Observation 没有 student_id 字段
  ↓
LearningEvent.from_observation 的 fallback:
  student_id = getattr(observation, "student_id", None) or getattr(observation, "skill_id", "")
  → 落到 skill_id (如 "python.loops")
  ↓
/api/answer 经 Plugin 路径 (v0.85.0-d):
  _update_via_plugin_or_legacy → bus.publish("response_submitted", event)
  → PluginRuntime._handle_response_submitted 用 event.student_id (= skill_id)
  → state_factory(skill_id) → _get_or_create_student 创建幽灵学生
  → 幽灵学生 state 被更新, 真实学生 (lbc002) state 永远不动
  ↓
save_student_state 只写 last_active_at=now → 看起来"写入成功" (persisted=True)
```

**为什么以前没暴露**: v0.85.0-d 前 submit_answer 走 legacy `engine.update(state, obs)` 直接更新真实学生; Plugin 路径激活后 subscriber 用错 student_id。`EventBus.publish` 吞异常 (success=0 才走 legacy), subscriber 正常返回但 mutate 的是幽灵对象 → 无任何报错。

**第二个被掩盖的问题**: `log_event=False` (replay/simulate) 契约要求不污染 event_log, 但 `FeatureExtractor.extract` 无条件 emit `response_submitted` — 以前事件被 skill_id 错标, `load_events(真实学生)` 查不到掩盖了污染; student_id 修正后暴露。

## 修复 (3 处)

1. `ecos/cta/event_log.py`: `from_observation` / `from_response_submitted` 加 `student_id` 显式参数 (缺省仍走旧 fallback, 向后兼容)
2. `web/api/belief.py` `_update_via_plugin_or_legacy`: 传真实 `student_id`
3. `ecos/cta/feature_extractor.py` + `belief_engine.py`: `extract` 加 `log_event` 参数并传导, replay/simulate 不再污染 event_log

## 回归测试 (+2)

- `test_plugin_sdk.py::TestResponseSubmittedStudentIdRouting` — 事件携带真实 student_id; sid-aware state_factory 下更新落在真实学生、不创建 skill_id 幽灵学生
- `test_learning_event_unification.py` 更新 — FeatureExtractor 双写事件关联真实 student_id
