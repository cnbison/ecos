## 1. 背景与定位

### 1.1 为什么是 v0.93

v0.92.0-d 完成 Phase 7+ 抽象推演 #5 (HumanTwinSnapshot ActionHistory 占位兑现). CognitiveTwinAgent 4-tuple 闭合. POMDP Policy 现状:

- ✅ 4 状态 (Engaged / Frustrated / Bored / Confused) + Bayesian belief
- ✅ 依赖型 T(s'|s, a) (n_states × n_states × n_arms)
- ✅ R(s, a) Beta posterior (alpha / beta per (s, a))
- ✅ bayes_update(action, observation)
- ✅ PBVI 完整算法 (α-vector + backup + 收敛)
- ✅ POMDPPolicy 默认 use_pbvi=True + use_learned_t_r=True + min_samples=5 冷启动
- ✅ Runtime + PolicyABTest 集成 + 3-way A/B
- ❌ **无 diagnostic surface** — select_arm 之外的字段 (T/R/belief/coverage/演化) 不可观测
- ❌ **无 timed snapshot** — T/R 演化历史不可追溯
- ❌ **无 Plugin SDK 集成** — diagnostic 无法被前端/event consumer 消费

v0.92 final 留下的 3 个候选缺口 (per 12-kernel-mapping §8.2):

- ⚠️ 第一方 plugin 库 (Kernel-only SDK 提供 plugin 基类 + register API, v0.94+ 应用层复用)
- ❌ **POMDP T/R 后验可视化** (display layer + Kernel 内字段暴露)
- ❌ Teacher/Parent Dashboard (Kernel-first 主动推迟项, Bisen 2026-08-06 拍板)

v0.93 范围: POMDP T/R 后验可视化 (Kernel-only, 不进前端) — 跟 Kernel-first 一致. 第一方 plugin 库留 v0.94+. Teacher/Parent Dashboard 跟 Kernel-first 主动推迟项矛盾, 留 Kernel 稳定后 (per Bisen 2026-08-06 战略).

### 1.2 战略选择 (Bisen 拍板 2026-08-12)

per Bisen 决策 2026-08-12 (5 决策全部拍板):

- **主轴**: POMDP T/R 后验可视化 — Kernel 内字段暴露, v0.95+ dashboard 可复用.
- **诊断 API 形态**: Structured dataclass payload — POMDPDiagnostic frozen dataclass + to_dict/from_dict + schema_version="0.93.0". Kernel 统一出口, v0.95+ dashboard 可直接反序列化渲染.
- **覆盖范围**: T + R + belief 三件套 + coverage 字段. 一次性暴露 POMDP 全部可观测字段. coverage 是冷启动判断核心 (min_samples=5 阈值达标).
- **演化追踪方式**: Timed snapshots (每 N=50 次 update_t_r 截一个, cap K=10). v0.95+ dashboard 可看趋势. 跟 v0.81 EventLog retention (max_per_student cap) 同 pattern.
- **集成层 + 持久化**: Runtime + LCAEngine + Plugin SDK 全栈 + DB column. lca_state 表加 pomdp_diagnostic TEXT 列 + schema_version 校验. 跟 v0.92.0-d LCAEngine 4-tuple dump/load 完全 parallel.

不选 X (5 决策每项都有不选理由):

- 主轴: 不选第一方 plugin 库因为 Kernel-first 战略下 Kernel 内字段暴露优先 (Plugin SDK 100% production 已 v0.91.0-e 完成, 缺 first-party 实施但可推迟); 不选 Teacher/Parent Dashboard 因为跟 Kernel-first 主动推迟项矛盾.
- 诊断 API 形态: 不选 Raw ndarray wrapper 因为缺 schema, v0.95+ 反序列化需重写 adapter; 不选 Event log style 因为事件量大, EventLog retention 压力 + 增加 LearningEventType 枚举.
- 覆盖范围: 不选 T + R 双件套因为 belief 是 POMDP 跟 LinUCB/Thompson 最大区别, 不暴露等于丢核心; 不选 T + R + belief + 学习曲线因为跟演化追踪决策冲突, API 表面变大.
- 演化追踪: 不选当前快照 only (lazy) 因为丢失演化趋势, v0.95+ dashboard 仅能看当前不能看趋势; 不选 EventLog snapshots 因为每 1 update emit 1 event → 事件量大 + retention 压力.
- 集成层 + 持久化: 不选 Runtime + LCAEngine only (Kernel only, 不进 Plugin) 因为减少 surface 但 v0.95+ dashboard 拿不到; 不选 Plugin SDK only 因为把 diagnostic 走 event subscription = 跟演化追踪决策冲突; 不选 in-memory only 因为重启丢失 (Bisen 之前明确反对, v0.57.0 LCA 持久化教训).

### 2.3 POMDPDiagnostic 数据结构

```python
@dataclass(frozen=True)
class POMDPDiagnostic:
    """POMDP 诊断 surface (v0.93.0-a).

    一次性暴露 POMDP 全部可观测字段: T/R/belief/coverage/most_likely_state.
    v0.95+ Teacher/Parent Dashboard 可直接 to_dict() 反序列化渲染.

    三件套 + coverage 字段:
    - T: TransitionPosteriorSnapshot (Dirichlet posterior mean + count + alpha0)
    - R: RewardPosteriorSnapshot (Beta posterior mean + alpha + beta + variance)
    - belief: 4 状态 posterior (跟 POMDPPolicy.belief 一致)
    - coverage: per (s, a) 样本数 (冷启动判断用, min_samples=5 阈值达标)

    跟 POMDPPolicy / CognitiveTwinAgent schema_version="0.93.0" 同步.
    """
    T: TransitionPosteriorSnapshot
    R: RewardPosteriorSnapshot
    belief: np.ndarray  # shape (n_states,)
    coverage: np.ndarray  # shape (n_states, n_arms)
    most_likely_state: int
    last_updated: datetime
    schema_version: str = "0.93.0"

    def to_dict(self) -> Dict[str, Any]:
        return {
            "T": self.T.to_dict(),
            "R": self.R.to_dict(),
            "belief": self.belief.tolist(),
            "coverage": self.coverage.tolist(),
            "most_likely_state": int(self.most_likely_state),
            "last_updated": self.last_updated.isoformat(),
            "schema_version": self.schema_version,
        }

    @classmethod
    def from_dict(cls, state: Dict[str, Any]) -> "POMDPDiagnostic":
        if state.get("schema_version") != "0.93.0":
            raise ValueError(f"Unsupported schema_version: {state.get('schema_version')}")
        return cls(
            T=TransitionPosteriorSnapshot.from_dict(state["T"]),
            R=RewardPosteriorSnapshot.from_dict(state["R"]),
            belief=np.asarray(state["belief"], dtype=float),
            coverage=np.asarray(state["coverage"], dtype=int),
            most_likely_state=int(state["most_likely_state"]),
            last_updated=datetime.fromisoformat(state["last_updated"]),
        )
```

### 3.4 LCAEngine.get_pomdp_diagnostic + _pomdp_diagnostic dict

```python
# ecos/lca/orchestrator.py (NEW methods)
def get_pomdp_diagnostic(self, student_id: str) -> POMDPDiagnostic:
    """v0.93.0-b: 拿 student_id 的 POMDPDiagnostic.

    路径:
    1. self._pomdp_diagnostic dict 拿 (select_intervention pomdp path auto-collect 后写入)
    2. miss 时 _log.warning + 调 POMDPPolicy.get_diagnostic lazy collect (cold start)
    3. POMDPPolicy not configured (policy_type != "pomdp") → raise RuntimeError
    """
    if student_id in self._pomdp_diagnostic:
        return self._pomdp_diagnostic[student_id]
    _log.warning("LCAEngine.get_pomdp_diagnostic: miss sid=%s, lazy collect", student_id)
    learner = self.policy_learner._get_learner(student_id)
    if learner is None or learner.pomdp is None:
        raise RuntimeError(f"POMDPPolicy 未初始化 for student_id={student_id}")
    diagnostic = learner.pomdp.get_diagnostic()
    self._pomdp_diagnostic[student_id] = diagnostic
    return diagnostic


# self._pomdp_diagnostic dict (NEW per-student pattern)
# 跟 self._cognitive_twin / self._last_intervention / self._last_observation 一致
self._pomdp_diagnostic: Dict[str, POMDPDiagnostic] = {}
```

def _update_t_r(self, arm: int, observation: int, reward: float) -> None:
