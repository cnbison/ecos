## 1. 背景与定位

### 1.1 为什么是 v0.90

v0.89.0-d 完成 Phase 7+ 抽象推演 #2 (PBVI 雏形 + 完整集成 Runtime). POMDP Policy 现在有:

- ✅ 4 状态 + Bayesian belief
- ✅ 依赖型 T(s'|s, a) (n_states × n_states × n_arms)
- ✅ R(s, a) **固定 init** (per design doc §4.2)
- ✅ bayes_update(action, observation)
- ✅ PBVI 完整算法 (α-vector + backup + 收敛)
- ✅ POMDPPolicy 默认 use_pbvi=True
- ✅ Runtime + PolicyABTest 集成

v0.89.0-c 留下的 3 个缺口:

- ⚠️ R(s, a) 固定 init, 不学
- ❌ T(s'|s, a) 固定 init, 不学 (跟 v0.88.0-c 同, 仅靠 init 启发式)
- ❌ PBVI 用固定 T/R 求解, 不消费学习结果

v0.90 范围: 让 T/R 都通过贝叶斯 posterior 在线学, PBVI 重新求解时消费 posterior 的 MAP point estimate.

### 1.2 战略选择 (Bisen 拍板 2026-08-12)

per Bisen 决策 2026-08-12 (5 决策全部拍板):

- **主轴**: POMDP T/R 在线学习 — 选 Beta-Multinomial conjugate posterior (跟 Thompson Sampling 同栈, 后验解析, 计算轻).
- **T 算法**: Beta-Multinomial conjugate (每 (s,a) 一个 Dirichlet, update (s,a,s') increment, 先验 α0=1 uniform).
- **R 算法**: Beta conjugate posterior (每 (s,a) 存 (α, β), update 后 α += reward, β += 1-reward, 先验 α=β=1).
- **Update 接口**: 扩展 `update(arm, ctx, reward)` 加 `observation=None` 默认参数, 同时新增 `update_t_r(arm, obs, reward)` 内部接口.
- **PBVI 消费**: MAP point estimate (每次 PBVI.solve 前取 posterior mean).
- **冷启动**: Posterior 均匀先验 + 最小样本后才重 solve (证据 < 5 之前用 init, 之后切换到学).
- **4 sub-commit 节奏**: a/b/c/d (跟 v0.86/v0.87/v0.88/v0.89 一致).

不选 X (5 决策每项都有不选理由, 拍板理由已在 AskUserQuestion 给出):

- T 算法: 不选 ML 频率更新 (Laplace 平滑) 因为无不确定性表达, 跟 belief 贝叶斯脱节; 不选 BNN/VB 因为实现重.
- R 算法: 不选 Normal-Inverse-Gamma 因为 reward ∈ [0,1] 不需高斯假设; 不选固定 init 因为不合 v0.89 design §1 "依赖型 T+R 升级".
- Update 接口: 不选仅 `update(arm, ctx, reward)` 无 obs 因为 T/R 学习需要 obs; 不选仅新增方法因为接口 boilerplate 多, 同时学 T/R 与原 update 拆分让 LCAEngine 调用复杂.
- PBVI 消费: 不选 Posterior sample (POMCP) 因为实现重, 跳 v0.91+; 不选自适应 sample 因为难调, 超 v0.90 范围.
- 冷启动: 不选冷启动退到固定 init 因为额外分支; 不选每次 update 重 solve 因为冷启动期不稳且频率高费 CPU.

### 2.2 关键不变量

- **Posterior 跟 POMDPPolicy 字段对齐**: `transition` shape (n_states, n_states, n_arms), `reward` shape (n_states, n_arms). posterior 数据结构跟 POMDPPolicy init 字段同 shape, mean() 后可直接赋值.
- **Posterior 不可变 dataclass**: 跟 AlphaVector frozen 同模式, 防止 solver 内部 mutation 干扰外部.
- **update 增量**: 每次 update 仅 O(n_states) 或 O(1), 不重算 posterior.
- **mean() 是派生**: posterior mean 仅在调用时算 (cached=False), 不存中间值.
- **Posterior 数据结构独立于 POMDPPolicy**: POMDPPolicy 不持有 posterior, posterior 走单独路径 (避免 POMDPPolicy 接口同构 LinUCB 破坏).
- **防御性自检 [8] 仍 hard block**: TransitionPosterior / RewardPosterior 不持有 BeliefState 引用, 不触发 mutation site 报警.

### 2.3 Beta-Multinomial conjugate 算法

```python
@dataclass(frozen=True)
class TransitionPosterior:
    """T(s'|s, a) Dirichlet 多项式 posterior (v0.90.0-a).

    每 (s, a) 对一个 Dirichlet (n_states 多项式), update (s, a, s') increment.
    posterior mean = (count[s, a, s'] + alpha0) / Σ_s' (count[s, a, s'] + alpha0)
    """
    count: np.ndarray  # shape (n_states, n_states, n_arms)
    alpha0: float = 1.0

    def update(self, s: int, a: int, s_next: int) -> None:
        self.count[s, a, s_next] += 1  # 实际实现走 mutation, 在 allowlist 里 (跟 append_trajectory_snapshot 同模式)

    def mean(self) -> np.ndarray:
        n_states = self.count.shape[0]
        posterior = self.count + self.alpha0
        return posterior / posterior.sum(axis=1, keepdims=True)
```

### 2.4 Beta conjugate posterior 算法

```python
@dataclass(frozen=True)
class RewardPosterior:
    """R(s, a) Beta conjugate posterior (v0.90.0-a).

    每 (s, a) 存 (α, β), update 后 α += reward, β += (1 - reward).
    posterior mean = α / (α + β) (Bayes estimator).
    """
    alpha: np.ndarray  # shape (n_states, n_arms)
    beta: np.ndarray   # shape (n_states, n_arms)
    alpha0: float = 1.0

    def update(self, s: int, a: int, reward: float) -> None:
        self.alpha[s, a] += reward
        self.beta[s, a] += (1.0 - reward)

    def mean(self) -> np.ndarray:
        return self.alpha / (self.alpha + self.beta)
```

### 2.5 防御性自检 [8] allowlist 计划

`TransitionPosterior.update` / `RewardPosterior.update` 含 `self.count[s, a, s_next] += 1` / `self.alpha[s, a] += reward` 直接 mutation. 需加 allowlist:

- `TransitionPosterior.update` (跟 `BeliefState.append_trajectory_snapshot` 同模式: 增量更新数据结构)
- `RewardPosterior.update` (同上)

跟 v0.83.0-b add_evidence / v0.88.0-b set_domain_extension / v0.88.0-d _last_observation 一样, allowlist 扩张是合理的 (新数据结构维护).

### 4.2 关键不变量

- **接口同构 LinUCB/Thompson**: `update(arm, ctx, reward, observation=None)` 默认参数兼容老调用 (老调用不传 observation 走 v0.89.0-d 路径).
- **use_learned_t_r=True 默认**: 不破坏 v0.89.0-d PBVI 默认行为, 但首次 `update(arm, ctx, reward, obs=0)` 后触发 lazy init posterior, posterior mean 立即影响下次 PBVI.solve.
- **posterior lazy init**: 首次 `_update_t_r` 时根据 self.n_states / self.n_arms 构造 TransitionPosterior (count=zeros + alpha0=1) + RewardPosterior (alpha=ones + beta=ones).
- **PBVI 消费 posterior mean**: `solve_pbvi` / `select_arm` 在调 PBVI.solve 前, 若 `use_learned_t_r and posterior is not None`, 用 `posterior.mean()` 替换 init T/R (临时 mutation, 调完还原 — 但 mutation 触发防御性自检 [8]).
- **防御性自检 [8] 应对**: 不直接 mutation `self.transition`, 而是把 posterior mean 作为 PBVI 输入参数传入 (避免 allowlist 扩张). PBVI.backup_step 接收 transient T/R, 不依赖 self.transition.
- **PBVI 失败 fallback QMDP**: 跟 v0.89.0-c 同, posterior mean 异常 → fallback QMDP.
