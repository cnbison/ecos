## 1. 背景与定位

### 1.1 为什么是 v0.85

v0.84.0 完成 Plugin SDK 雏形 (1/4 endpoint, /api/answer 改造) + Event Engine 100%. 下一阶段: 把剩余 3 endpoint (judge / dual_agent / lca) 全部走 Plugin path, 让 production 真激活 Plugin 架构.

per [project-strategy-kernel-first](../memory/project-strategy-kernel-first.md) Kernel-first 战略 + 12-kernel-mapping §8.3:
- v0.85 完成 Plugin SDK 全量 (4 endpoint)
- v0.86+ Phase 7+: Twin → Human Twin 抽象 + Multi-Domain 扩展

### 1.2 战略选择: 4 endpoint 全量 + Production activation 一起

v0.84.0-d 只改 1 endpoint, production 没激活 (PluginRuntime 未在 Flask startup 注册). v0.85 必须:
1. 完成剩 3 endpoint 改造 (Plugin 原则验证)
2. Production activation (Flask startup 注册 PluginRuntime, 让 production 真走 Plugin 路径)
3. 4 个新 event_type frontend stub (hint/idle/goal_change/reflection, kernel-mapping §2.4 收尾)

不只做 §6 收尾, 顺手做 §2.4 event_type frontend 占位. 原因: 4 个 event_type 已定义 (v0.84.0-a LearningEventType enum 7 值, v0.85.0-a 加 JUDGE_COMPLETED = 8 值), 不接前端等于没验证.

## 6. 3 个设计决策 (Bisen 拍板 2026-08-11)

### 6.1 /api/judge 改造方向

**决策**: **加 judge_completed event (observability, Runtime subscriber 仅日志)**

**为什么不是驱动 state**: /api/judge 是 LLM judge 只读路径, 不写 state. /api/answer 才是 state 写入路径. judge_completed event 用于观测性 (e.g. compute ECE 时回放), 不重复 state 更新.

### 6.2 Production activation 启动点

**决策**: **`if __name__ == "__main__"` 块启动前 `plugin_runtime.start()`**

**为什么不用 before_first_request**: Flask 2.3+ before_first_request deprecated. if __name__ 块更稳定, 跟现有 Flask app.run 同一启动点.

### 6.3 v0.85 实施节奏

**决策**: **4-sub-commit (跟 v0.80/0.81/0.82/0.83/0.84 同节奏)**

**为什么不是 1 commit**: 1 commit regression 风险集中. 4 sub-commit 每版独立可测可回滚.
